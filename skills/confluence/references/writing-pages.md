# Writing pages

`page create / update / delete / move / copy` modify Confluence. They write
exactly once and are never retried automatically. Only run them when the user
explicitly asked for that change — never write speculatively.

## Safety: --dry-run and --yes

- **Every** write command accepts `--dry-run`: it prints the exact HTTP request
  (`method`, `url`, `payload`) that *would* be sent and sends nothing. Use it to
  preview a change before committing to it.
- `page delete` additionally requires `--yes` to proceed. Without `--yes` it
  fails when stdin is not a terminal (the agent case) and prompts when it is.

## Body formats

`create` and `update` take a body via `--body <text>` or `--body-file <path>`
(`-` reads stdin), interpreted per `--body-format` (not `--format`, which is the
global output format):

| `--body-format` | Meaning |
|-----------------|---------|
| `storage` (default) | raw Confluence storage-format XHTML |
| `wiki` | Confluence wiki markup, converted server-side |
| `markdown` | Markdown, converted to storage format client-side (best-effort) |

`markdown` covers headings, paragraphs, bold/italic, inline + fenced code,
links, lists, blockquotes, tables, images and rules. Unsupported constructs
(task lists, raw HTML, footnotes) degrade to plain text with a `note:` on stderr.

## AI attribution (agent writes)

For a page body you author, add one attribution at the top linking back to the
tool. On an existing page, describe the sections you changed instead of claiming
the human's whole page was AI-generated. Preserve any existing attribution once;
a title-only update does not require rewriting the body. Human-supplied text is
not AI-authored. These are agent conventions, not automatic CLI behavior.

- **storage body** (`--body-format storage`) — prepend an Info macro:

  ```xml
  <ac:structured-macro ac:name="info">
    <ac:rich-text-body>
      <p>[AI] This page was generated by AI via <a href="https://angelmsger.github.io/confluence-cli/">confluence-cli</a>.</p>
    </ac:rich-text-body>
  </ac:structured-macro>
  ```

- **markdown body** — prepend a single callout line:

  ```markdown
  > [AI] This page was generated by AI via [confluence-cli](https://angelmsger.github.io/confluence-cli/).
  ```

- **wiki body** — use Confluence wiki link syntax, for example:

  ```text
  \[AI\] This page was generated by AI via [confluence-cli|https://angelmsger.github.io/confluence-cli/].
  ```

Use the page's language and describe the actual contribution, such as "AI
updated the deployment checklist via confluence-cli." Keep the URL, tool label,
and ASCII `[AI]` marker unchanged; emoji can fail on Data Center databases that
cannot store 4-byte characters. Keep one existing banner rather than stacking
another.

## Create

```bash
confluence-cli page create --space ENG --title "Release Notes 1.2"
confluence-cli page create --space ENG --title "Plan" --parent 12345 \
  --body-format markdown --body-file ./plan.md
```

`--space` and `--title` are required. `--parent` (ID or URL) nests the page.
Returns the new page's `id`, `title`, `url` and `version`.

## Update

```bash
# change only the title; the body is kept
confluence-cli page update 12345 --title "Release Notes 1.3"
# save the current storage body; stdout includes the version read
confluence-cli page get 12345 --as raw --body-format storage -o current-page.xml
# after applying the requested edit to the file, assert that version
confluence-cli page update 12345 --body-format storage --body-file ./current-page.xml --version 7
```

Pass at least one of `--title` / `--body` / `--body-file`. The new version is
the current version + 1. The client fetches the current version first; pass
`--version <n>` to assert the version you last read instead. A `--version`
mismatch fails with `PAGE_VERSION_CONFLICT` (exit code 11). Re-fetch the current
raw storage body and version, merge the intended change into that body, and
retry with the newly read version. Advancing `--version` while keeping a stale
body would overwrite concurrent edits. `--minor` marks a minor edit; `--message`
sets the version comment.

Body updates replace the whole page. Edit the raw storage source for existing
pages, preserving unrelated prose, macros, images, links, tables, and embedded
content. A rendered Markdown copy or scoped section cannot preserve that
structure. Use Markdown for newly authored content or an explicitly requested
replacement. Check the local diff before the dry run, then read back the changed
section after writing; summarize what changed with the page link and version.

## Delete

```bash
confluence-cli page delete 12345 --yes            # move to trash
confluence-cli page delete 12345 --purge --yes    # permanently remove
confluence-cli page delete 12345 12346 --yes      # batch: several IDs at once
```

`page delete` accepts several IDs, or a single `-` to read newline-separated IDs
from stdin. With more than one it returns an `{items, has_more}` aggregate with a
per-page `ok`/`error`, deletes every one even if some fail, and exits non-zero on
any failure. `--yes` / `--purge` / `--dry-run` apply to the whole batch.

## Move and copy

```bash
confluence-cli page move 12345 --target-parent 67890
confluence-cli page move 12345 --target-space DOCS
confluence-cli page copy 12345 --title "Copy of Plan" --space DOCS
```

`move` reparents a page and/or moves it to another space. `copy` is **shallow**:
it duplicates the title and body only — not child pages or attachments.

## Version history and restore

```bash
# list a page's versions (newest first)
confluence-cli page history 12345

# exact version events from several pages (or pass '-' to read IDs from stdin)
confluence-cli page history 12345 67890 --actor me --since 24h

# restore the page to an earlier version
confluence-cli page history 12345                       # find the version number
confluence-cli page restore 12345 --version 3
confluence-cli page restore 12345 --version 3 --message "roll back bad edit"
```

Each history entry has `number`, `when`, `by`, `actor`, `page`, `message` and
`minor_edit`. `actor` carries the stable Cloud account ID or Data Center
username/user key when available; `page` identifies the source in batch output.
`--actor` accepts `me` or a selector found with `user search`. Filtering
supports `--actor`, `--since`, or `--from` / `--to`. Time-bounded queries read
newest-first and stop after crossing their lower bound; actor-only single-page
filtering may scan the full history. Batch/stdin queries reject `--cursor`. See
[searching-cql.md](searching-cql.md) for time semantics, backend compatibility,
partial-batch behavior, and the exact edit discovery workflow.

`restore` is **non-destructive**: it republishes the chosen version's body as a
new version, so the history is never lost. Use `--dry-run` to preview it.

## Watching a page

```bash
confluence-cli page watch 12345          # subscribe to the page's notifications
confluence-cli page unwatch 12345        # unsubscribe
confluence-cli page watch-status 12345   # report whether you watch the page
```

These act on the user behind the configured credentials.
